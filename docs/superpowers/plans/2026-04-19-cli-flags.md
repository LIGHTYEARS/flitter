# Plan 17: Top-Level CLI Flags (N1 + N10)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add missing top-level CLI flags: `--print`, `--pipe`, `--max-turns`, `--system-prompt`, `--model`, `--api-key`. Wire each flag into the appropriate mode so they affect LLM provider resolution, system prompt override, execute output format, and inference loop limits.

**Architecture:** The Commander.js program (`packages/cli/src/program.ts`) defines CLI options. The `resolveCliContext()` function (`packages/cli/src/context.ts`) extracts parsed options into a `CliContext` object consumed by mode runners. New flags extend both `createProgram()` options and `CliContext` fields. The mode runners (`execute.ts`, `headless.ts`, `interactive.ts`) and container creation in `main.ts` read the new fields.

**Tech Stack:** TypeScript, Commander.js, Bun test runner, `@flitter/cli`, `@flitter/flitter` (container)

**Amp reference:** `amp-cli-reversed/modules/1996_unknown_Yz0.js` lines 575-632 (CLI flag loop from `i$T` array), `amp-cli-reversed/chunk-006.js:38172-38280` (`i$T` flag definitions: `apiKey`, `sp`, `systemPrompt`, `mode`), `amp-cli-reversed/modules/2002_unknown_S8.js` (S8 context builder: `T.execute`, `T.streamJson`), `amp-cli-reversed/modules/1983_unknown_R3R.js` (R3R: system prompt override extraction from `--sp` / `--system-prompt`).

**Key amp behaviors:**
- `--execute [message]` is an optional-option: can be bare `--execute` or `--execute "message"`
- `--api-key` overrides stored API key for the session (hidden flag, `i$T` entry)
- `--system-prompt` / `--sp` provide custom system prompt text or file path; R3R reads it and Ms("systemPrompt", ...) sets it
- `--mode` selects agent mode (smart, code, ask, etc.) which affects model selection
- Amp has no `--print` or `--pipe` as top-level flags; `--print` exists only on `threads handoff` subcommand
- Amp has no `--max-turns` flag; the inference loop runs until the model stops or the user cancels

**Flitter adaptation:** We add `--print` (output only final text, no TUI), `--pipe` (alias for `--execute` with stdin), `--max-turns N` (limit inference loop iterations), `--system-prompt TEXT`, `--model MODEL`, `--api-key KEY`. These are Flitter-specific extensions beyond amp parity, except `--system-prompt`, `--model`, and `--api-key` which match amp's `--sp`, `--mode`, and `--api-key`.

```typescript
export function resolveCliContext(program: Command): CliContext {
  const opts = program.opts();
  const isTTY = Boolean(process.stdout.isTTY && process.stderr.isTTY);
  const print = Boolean(opts.print);
  const pipe = Boolean(opts.pipe);
  const executeMode =
    Boolean(opts.execute) || print || pipe ||
    (!process.stdout.isTTY && !Boolean(opts.streamJson));

  const rawMaxTurns = opts.maxTurns ? Number.parseInt(opts.maxTurns, 10) : undefined;
  const maxTurns = rawMaxTurns && Number.isFinite(rawMaxTurns) && rawMaxTurns > 0
    ? rawMaxTurns
    : undefined;

  return {
    executeMode,
    isTTY,
    headless: Boolean(opts.headless),
    streamJson: Boolean(opts.streamJson) || Boolean(opts.headless),
    verbose: Boolean(opts.verbose),
    userMessage: program.args.length > 0 ? program.args.join(" ") : undefined,
    print,
    pipe,
    maxTurns,
    model: opts.model as string | undefined,
    systemPrompt: opts.systemPrompt as string | undefined,
    apiKey: opts.apiKey as string | undefined,
  };
}
```
